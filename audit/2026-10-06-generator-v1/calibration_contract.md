# Контракт калибровки Generator V1

Generator V1 сейчас **внутренне согласован** и **поведенчески правдоподобен**. С реальным банком
он **не откалиброван**: агрегатов банка, кроме отчёта о каналах, у нас нет. Ниже — какие агрегаты
нужно запросить у банка, как каждый считается по выгрузке и что даёт синтетика сейчас.

Колонки таблиц:
- **synthetic** — среднее по трём scratch-мирам Generator 1.0.1 (seed 11, 12, 13, по 1000
  клиентов, окно 2024-01-01 → 2026-09-01), скрипт `diagnose.py report`, прогон 2026-10-07.
- **real** — значение банка. Пока unknown, кроме строк со статусом `reference`.
- **статус:**
  - `reference` — измерено банком, отчёт NBO/NBC/NBT от 2026-09-07;
  - `hypothesis` — полоса из плана, данными банка не подтверждена;
  - `unknown` — ни значения, ни полосы.
- **допуск** — с какой точностью synthetic обязан совпасть с real, когда real появится. Для
  `reference` — допуск отчёта, для остальных — предложение.

Определения записаны так, чтобы банк мог посчитать то же самое по своим данным.
- **Действие клиента** — маска `churn_baseline/churn/activity.is_client_action`, с G4:
  обязательства не считаются.
- **Визит** — успешный вход в приложение.
- **Клиент-месяц** — месяц, когда клиент уже пришёл в банк.

## Что делать, когда придут данные

1. Каждая строка получает real и статус `reference`. Сравнение — тем же `diagnose.py` на
   scratch-мире того же размера.
2. Параметры подбираются только из этого контракта и только по объёму и частотам. Подгонять
   долю оттока или метрику модели — нельзя.
3. Изменение параметров меняет байты выгрузки, поэтому поднимает `GENERATOR_VERSION`:
   - PATCH, если задуманные распределения не меняются;
   - MINOR или MAJOR, если меняются.
4. Статус «calibrated to real bank» в README появляется только для строк, вошедших в допуск.
