## Находки по убыванию влияния на ref-2026-10-09

### Н1. Нормировка aux-цели [USR] не совпадает с контрактом окна. Шаг зависит от разбиения на micro-batch'и. Тест инварианта идёт с выключенным aux

**Статус:** подтверждено. Код прочитан с обеих сторон, плюс scratch-прогон и расчёт на
длинах train эталона.

**Кто производит:**
- `model.py:525-529`: `RecentTypes.forward` возвращает `F.mse_loss(predicted, targets)`.
  Это среднее по `B` клиентам micro-batch'а × 4 цели × 54 типа, то есть среднее по
  клиентам **внутри micro-batch'а**.

**Кто потребляет:**
- `train.py:1373-1378`:
  `objective = out.loss + w * out.aux; (objective * out.count).backward()`.
  Aux умножается на число **MLM-целей** micro-batch'а.
- `train.py:1221-1226`: градиенты делятся на `window_targets`, то есть на число
  MLM-целей окна.

**Обещанный контракт:**
- `train.py:82-87`, `train.py:1204-1211`, README:1164-1167: «градиент среднего по ВСЕМ
  целям окна, цель в маленьком micro-batch весит столько же, сколько в большом».
- Для MLM это так. Для aux получается среднее по micro-batch'ам окна клиентских средних,
  взвешенное числом MLM-целей. Это не среднее по клиентам и не среднее по целям.

**Следствия:**

а) **При `grad_accum_steps > 1` градиент шага зависит от того, как окно разбито на
micro-batch'и.**
- Scratch-тест повторяет `test_one_big_batch_and_several_micro_batches_train_the_same`,
  только с aux. Перехвачен градиент всех параметров у `clip_grad_norm_`.
- При `usr_aux_weight=0` относительная разница 5·10⁻⁷ (шум последнего бита).
- При `usr_aux_weight=0.5` разница 0.67 по худшему параметру и 0.26 по `recent.proj`.

б) **Micro-batch без MLM-целей теряет aux целиком** (`train.py:1373`, aux внутри
`if out.count > 0`), хотя цели aux у его клиентов есть. В эталоне таких окон 0.

в) **В эталоне (accum = 1) вес клиента в aux за эпоху пропорционален 1/B.** B — число
клиентов в его micro-batch'е: от 1 до 10, в среднем 1.89; в 54% micro-batch'ей ровно
один клиент.

| Дециль клиентов по стоимости | Доля веса aux | При равном весе клиентов |
|---|---|---|
| Нижний, медиана 459 токенов | 5.9% | 10% |
| Верхний, медиана 58 008 токенов | 18.9% | 10% |

- Отношение весов отдельных клиентов — до 10×.
- Длинные истории получают втрое больше aux-сигнала, чем короткие.
- Сам `RecentTypes` описан как «средний квадрат ошибки по всем клиентам»
  (`model.py:448`).

**Тесты:**
- `tests/test_training_math.py:227` проверяет инвариант разбиения. Но `tiny()` ставит
  `usr_aux_weight=0.0` (`test_training_math.py:74`): синтетический мир без event_type.
- `tests/test_recent_types.py:148` проверяет только «голова учится и едет в чекпойнте».
- Инвариант зафиксирован в конфигурации, которая в проде не используется. Тест проверяет
  не то.

**Влияние:**
- На веса эталона: да. Пункт (в) — это сама целевая функция, по которой учился [USR].
  Пункт (а) в эталоне не действует.
- Прогон 2a (accum = 4) учился с иначе взвешенным aux, чем эталон. Его сравнение с
  эталоном слегка смешано. Величина, по оценке, небольшая: общий масштаб aux к MLM
  сохраняется.
- Насколько это сказалось на churn по [USR]: подозрение, величина неизвестна.

**Как подтвердить или исправить (дёшево):**
1. Без обучения: разбить уже посчитанные R² давности по [USR] из диагностики по корзинам
   длины истории. Если у коротких историй R² заметно ниже, перекос (в) виден.
2. Решить, какая нормировка aux нужна:
   - на клиента окна: aux как сумма по клиентам, умноженная на константу «целей на
     клиента», посчитанную по длинам до обучения, как `horizon`;
   - на micro-batch: оставить как есть, но поправить README и docstring.
3. В любом случае добавить тест разбиения с `usr_aux_weight>0` — голова `head()` из
   `test_recent_types` уже есть. Готовый образец: `probe/test_aux_partition.py`.

### Н2. Выбор чекпойнта и early stopping не видят aux; aux на val не считается вовсе

**Статус:** подтверждено.

**Что оптимизируется** (`train.py:1374-1377`):
- `CE_smooth(ε=0.1) + 1.0 · MSE_aux`.
- В эталоне MSE_aux за эпоху: 0.46 → 0.13. Это 6–19% величины MLM-потери.

**Чем выбирается:**
- `validate()` (`train.py:905-919`) копит в `Scores.add` (`train.py:302-314`) только
  `out.loss.item()`, то есть MLM.
- `out.aux` на val **вычисляется** (`model.py:617`, голова идёт и в eval) и выбрасывается.
- `best_checkpoint` и `stale` решаются по MLM val_loss (`train.py:1421-1428`,
  `train.py:1509-1510`).
- Сглаживание то же: модель одна, `label_smoothing` из конфига. Вес MLM тот же: по целям.
  Компонент aux отсутствует.

**Телеметрия:**
- `usr_aux_mean` пишется только в `telemetry.jsonl` (`train.py:1456`). Его не печатает
  `describe_epoch`, его не читает ни дашборд, ни другой код: grep по `src/` пуст.
- В README aux-потеря в описании логов не упомянута.

**Тест:** нет. Тесты early stopping подменяют `validate` целиком.

**Влияние:**
- Эталон: нет (best = last).
- Будущие прогоны: если MLM и aux расходятся по эпохам, best и early stopping выберут
  эпоху, где цель [USR] хуже. А именно [USR] идёт в downstream.
- Сравнение прогонов с разным `usr_aux_weight` по val_loss систематически в пользу
  меньшего веса.

**Дёшево:**
- В `validate` копить `aux · B` и число клиентов, писать `val_aux` в строку эпохи и в
  history.
- Отдельно решить: оставить выбор по MLM, сознательно, или выбирать по
  `MLM + w·aux`.

### Н4. MLM и aux делят один бюджет клипа; `max_grad_norm = 1.0` выбран до E1′

**Статус:** подозрение. Ниже — замер на CPU по трём micro-batch'ам.

- `train.py:1230`: клип по общей норме градиента `CE + 1.0·aux`.
- `train.py:1243`: проверка конечности смотрит на MLM-loss. Нечисловой aux ловится только
  через норму.
- Чья доля в норме определяет, сколько MLM-сигнала режет клип, по телеметрии не видно:
  `grad_norm` — это норма суммы.

**Замер** (`scripts/grad_parts.py`, `scripts/grad_parts.out`):
- CPU fp32, SDPA, режим train, одинаковый dropout у трёх проходов.
- Три micro-batch'а маски эпохи 1, бюджет 6000, только клиенты ≤ 400 событий. Длинные
  клиенты на CPU в разумное время не считаются: на полном бюджете за 10 минут не прошёл
  ни один проход.

| Веса | MLM-loss | aux MSE | ‖g_MLM‖ | ‖g_aux‖ | ‖g_MLM + g_aux‖ |
|---|---|---|---|---|---|
| init | 8.75–8.82 | 8.1–8.5 | 2.85–3.25 | 6.5–6.7 | 7.1–7.5 |
| epoch_05 | 1.85–2.05 | 0.04–0.14 | 0.64–0.97 | 0.27–0.49 | 0.70–1.04 |

Что видно:
- **На старте aux доминирует в норме: ‖g_aux‖ ≈ 2.2 × ‖g_MLM‖.** Норма первого шага в
  телеметрии эталона — 7.54, это совпадает с замером ‖g_MLM + g_aux‖ на init.
- Клип 100% первых 200 шагов (медиана нормы 7.3 → 2.1) режет в основном направление aux.
  Компонента MLM получает около 0.4 нормы окна.
- На эпохе 5 aux даёт ещё 30–50% нормы MLM. Без него часть шагов была бы под порогом 1.0.

**Статус:** доля aux в норме измерена, но только на коротких клиентах. Сколько
MLM-сигнала клип отнял из-за aux на всём прогоне — подозрение.

**Тест:** нет.

**Влияние:** на веса — через долю клипа (известно: 86% → 49%); теперь видно, что
заметная её часть приходится на aux. Нужны ли отдельный порог, другой вес aux или
отдельная нормировка — решение владельца.

**Дёшево:**
- Подтвердить на всём распределении клиентов: тот же замер на GPU по нескольким
  настоящим micro-batch'ам эталона. Это не обучение, но GPU занят другим агентом — только
  по команде.
- Либо писать в телеметрию шага две нормы (MLM и aux) отдельными backward. Это стоит
  лишнего прохода, поэтому лучше как разовая диагностика.

### Н7. Weight decay на всех 105 тензорах: LayerNorm, смещения, таблица эмбеддингов, голова aux

**Статус:** подтверждено. Влияние мало, это решение дизайна, а не нарушение контракта.

- `train.py:1030-1035`: одна группа `AdamW(model.parameters(), weight_decay=0.01)`.
- В чекпойнте одна param_group на 105 тензоров. Из них 68 одномерных: веса и смещения
  LayerNorm, все bias. Плюс связанная с выходом таблица 5760×128 и `recent.proj`.
- Суммарное сжатие без градиента: `exp(−0.01 · Σlr) = exp(−0.0371) = 0.964`, то есть
  3.6% за прогон. Σlr = 3.707 по телеметрии.
- Усиления LayerNorm тянутся к 0, а не к 1. Строки редких токенов в связанной таблице
  гаснут.

**Тест:** нет.

**Влияние:** веса меняются, но на уровне процентов. На выводы эталона, по оценке, не
влияет.

**Дёшево:** две группы (decay для 2-D весов, без decay для 1-D и, по выбору, таблицы).
Менять только вместе с новым эталоном.
