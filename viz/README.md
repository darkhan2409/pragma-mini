# PRAGMA 3D Demo

Интерактивная визуализация pipeline: как события одного банковского клиента проходят
через PRAGMA и становятся Client Embedding. Два режима:

- **PRESENT** — 20 шагов с плавной камерой и короткими подписями; шаги 14, 19 и 20 —
  2D-экраны (живой дашборд обучения, главный вывод, возможные причины и проверки);
- **EXPLORE** — свободная камера, клик по блоку открывает детали архитектуры.

Приложение локальное: Vite, React, React Three Fiber, Framer Motion (`motion`),
Recharts, zustand. Шрифты Inter и JetBrains Mono лежат в `public/fonts` — внешних
запросов нет.

## Установка

Node 22 через nvm в WSL: npm из Windows сюда не подходит. nvm не загружается сам в
неинтерактивной оболочке, поэтому каждая команда начинается с `source ~/.nvm/nvm.sh`.

```bash
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.3/install.sh | bash   # один раз
source ~/.nvm/nvm.sh
cd viz
nvm install          # версия из .nvmrc
npm ci
```

`which node` должен указывать в `~/.nvm`.

## Данные сцены

Все числа сцены — словарь, параметры, конфиги, демо-клиент, окна, план шагов — берутся
из `src/data/pragma_demo.json`. Руками туда ничего не вписывается: файл собирает
экспортер, который только читает `data/`. Запуск из корня проекта:

```bash
python viz/scripts/export_demo.py                            # код и данные конвейера
python viz/scripts/export_demo.py --run data/runs/w4-b0      # + сводка прогона
python viz/scripts/export_demo.py --run data/runs/w4-b0 \
    --checkpoint data/runs/w4-b0/best_checkpoint.pt          # + числа обученной модели
```

Ещё есть `--group` (по умолчанию `train`), `--client` (по умолчанию `c000728448910`)
и `--out`.

Что читает экспортер:

- словарь `data/03_vocab`: счёт по видам, имена токенов, диапазоны корзин, куски BPE;
- lineage этапов 06 и 07: конфиги энкодеров и число параметров;
- `MlmConfig` и `MaskingConfig`;
- строку клиента из набора 05 и его сырые события из 02. События сопоставляются
  через `encode_event`, поэтому событие, которое в 02 и 05 кодируется по-разному,
  останавливает экспорт;
- константы даунстрима и метрики CatBoost из `churn_baseline/reports/metrics.json`;
- с `--run` — сводку `telemetry.jsonl`.

С `--checkpoint` модель загружается на CPU через `load_trained` (sdpa), примерно
за 30 с. Считаются две вещи:

- строки внимания `[USR]` энкодера истории по блокам и головам —
  `usr_attention_rows` из `src/mlm/diagnostics.py`; расхождение с настоящим выходом
  внимания записывается;
- предсказание для скрытой суммы сквозного события: top-5 по всему словарю и
  вероятности корзин.

Самопроверки останавливают экспорт с ошибкой, если что-то не сходится:

- виды токенов не покрывают словарь;
- лента клиента не сходится со строкой набора;
- сумма параметров расходится с lineage;
- веса собраны под другой словарь;
- у сквозного события сумма не закодирована, и шагу MLM нечего скрыть.

**Повторный экспорт нужен** после пересборки конвейера (другие данные или словарь) и
после нового чекпойнта. Дата экспорта и отпечаток словаря видны в правом нижнем углу
сцены.

## Запуск

```bash
source ~/.nvm/nvm.sh && cd viz
npm run dev                          # разработка: http://127.0.0.1:5173
npm run build && npm run preview     # сборка: http://127.0.0.1:4173
npm test                             # vitest
```

Сервер слушает только `127.0.0.1`; из WSL адрес открывается в браузере Windows.
Каталог данных — `../data`, другой можно задать в `PRAGMA_DATA_DIR`.

**Во время обучения** демо открывается только в браузере на встроенной графике
(настройка графики Windows для браузера). Иначе WebGL займёт память видеокарты,
и обучение упадёт.

Режим низкой мощности — клавиша `L` или `?lowpower=1`: рендер в разрешении 1× вместо
1,5× и без фоновой анимации цикла обучения.

## Управление

PRESENT:

| Клавиша | Действие |
|---|---|
| → · Space · PageDown · Enter · клик | вперёд |
| ← · PageUp · Backspace | назад |
| Home · End | первый · последний шаг |
| `S` | список шагов |
| `E` | EXPLORE |
| `H` | скрыть подписи |
| `F` | полный экран |
| `L` | низкая мощность |
| `?` | справка |

- Клавиши работают и в русской раскладке.
- Кликер для презентаций шлёт PageUp и PageDown и тоже работает.
- Клик листает и на 2D-экранах; клик по кнопке, ссылке, полю или выбору и выделение текста
  шаг не листают (`src/ui/advance.ts`).
- Шаг и бит хранятся в адресе (`#/present/10/1`): после перезагрузки показ
  продолжится с того же места.

EXPLORE:

- левая кнопка — вращение, правая — панорама, колесо — зум к курсору;
- клик по блоку подводит к нему камеру и открывает панель: компонент, файл кода,
  факты из экспорта, «Показать в презентации»;
- `Esc` закрывает панель, `R` возвращает общий вид, `P` — назад в PRESENT.

## Живая телеметрия (шаг 14)

Дашборд читает `telemetry.jsonl` прогона, который пишет `python -m src.mlm.train`.
Семантика та же, что у Streamlit-дашборда (`src/dashboard`): `telemetry/model.ts` — порт
`src/dashboard/telemetry.py`, и тесты повторяют `tests/test_dashboard.py`.

Источники данных:

- **API** (по умолчанию). Плагин Vite (`server/pragmaApi.ts`) работает и в `dev`, и в
  `preview`:
  - `/api/runs` — `data/12_train` и каталоги `data/runs/*`;
  - `/api/telemetry` отдаёт только целые строки с места прошлой остановки, не больше
    4 МиБ за раз. Если файл стал короче или его заменили, чтение начинается с начала.
    Прогон ищется по списку найденных, путь из запроса не склеивается;
  - опрос раз в 2–5 с, пока вкладка видна.
- **Файл.** Кнопка «файл…» открывает любой `telemetry.jsonl`. В Chromium файл
  перечитывается по мере роста.
- **Синтетика** — только в `npm run dev`, под баннером «СИНТЕТИКА», для проверки экрана.

## Обучение голов (шаги 17 и 18)

Шаг 17 — как учится логистическая регрессия над `[USR]`: данные train, перебор C по трём
фолдам (кривая log-loss на проверочном фолде и уровень «без модели»), финальная модель на всём
train и порог по прогнозам фолдов, оценка на val. Шаг 18 — как учится CatBoost на
handcrafted-признаках и на них же с `[USR]`: разбиение train, кривые PR-AUC на отложенной части
по числу деревьев с лучшей итерацией, порог, обучение на всём train и оценка на val. Числа — из
экспорта (`--run`): кривая перебора C из отчёта пробы, кривые CatBoost из `metrics.json`
churn_baseline (`holdout_curve`, в экспорте не больше 200 точек, лучшая итерация остаётся).

## Главный вывод и причины (шаги 19 и 20)

Шаг 19 показывает три сценария прогона из экспорта (handcrafted → CatBoost, `[USR]` →
LogisticRegression, handcrafted + `[USR]` → CatBoost): с `--run` экспортер берёт отчёт
`data/13_downstream/<прогон>/report.json` его пробы, если её векторы сняты с текущей выгрузки.

Шаг 20 — возможные причины, почему `[USR]` слабее handcrafted-признаков, по одной на бит. У
каждой — что проверить: эксперимент волны 4 со статусом его прогона или работа вне волны 4.
Причины и эксперименты — `src/content/wave.ts`; id экспериментов vitest сверяет с
`audit/2026-09-28-project/wave4/README.md`.

Статусы экспериментов выводятся только из файлов прогона `data/runs/w4-<id>`:

| Статус | Когда |
|---|---|
| NOT RUN | нет каталога или телеметрии |
| RUNNING | эпохи не все, файл менялся меньше 10 минут назад |
| INTERRUPTED | эпохи не все, файл давно не менялся |
| DONE | пройдены все запланированные эпохи или в `train.log` есть строка остановки |

ACCEPTED и REJECTED сервер не ставит: это решение человека. Оно записывается в
`src/data/wave4_decisions.json`:

```json
{ "E1": { "decision": "ACCEPTED", "date": "ГГГГ-ММ-ДД", "note": "на чём основано решение" } }
```

`decision` — `ACCEPTED` или `REJECTED`, `date` и `note` необязательны.

Файл входит в сборку: `npm run dev` подхватывает правку сразу, для `preview` нужен
`npm run build`.

## Числа из чекпойнта

Числа обученной модели идут под зелёной плашкой «ИЗ ЧЕКПОЙНТА». Это:

- веса внимания `[USR]` на шаге 10 — голова последнего блока с самым большим весом
  одного события, её 12 самых весомых событий и равномерная выборка по истории;
- вероятности предсказания на шаге 11 — top-5 по словарю и цель с её местом.

Если экспорт сделан без `--checkpoint`, на их месте рисуется схема. Какие пометки у какого
шага, задаёт `checkpoint` в `src/content/steps.ts`, а тесты проверяют, что пометки совпадают с
тем, что есть в экспорте.

## Устройство

```
scripts/export_demo.py     экспорт фактов → src/data/pragma_demo.json (только чтение data/)
server/                    плагин Vite: /api/runs, /api/telemetry, /api/wave4
src/
  data/                    demo.ts — типы экспорта и формат чисел; checkpoint.ts — выбор
                           событий шага 10 и строк шага 11; wave4_decisions.json
  content/                 steps.ts — 20 шагов (подпись, биты, регионы, кадр, экран,
                           пометки); shots.ts — кадры камеры; layout.ts — якоря регионов;
                           parts.ts — панели EXPLORE; wave.ts — причины и проверки
  store.ts                 режим, шаг, бит, выделение; синхронизация с адресом
  three/Stage.tsx          Canvas, камера, рельс
  three/Region.tsx         регион: focus / context / hidden, бит, зона клика EXPLORE
  three/primitives.tsx     подписи, карточки, фишки, глифы [128], линии, дуги, блоки
  three/regions/           по региону на шаг: Client, Event, Tokens, Embedding, EventEncoder,
                           Calendar, Profile, History, Rope, HistoryEncoder, Mlm, Backprop,
                           Loop, Final (Client Embedding и задачи), Heads (обучение регрессии
                           и CatBoost)
  telemetry/               порт читателя телеметрии, источники live / файл / синтетика
  ui/Overlay.tsx           верхняя панель, плашки, подпись, список шагов, справка, панель EXPLORE
  ui/screens/              TrainingDashboard, InsightScreen, CausesScreen (подгружаются лениво)
```

Все регионы стоят в одном мире вдоль оси X в порядке pipeline. Смонтированы они один
раз: шаг только ведёт прозрачность и появление элементов. Пока открыт 2D-экран,
canvas не рисует кадры.

## Проверки

```bash
cd viz && npm test && npx tsc -p tsconfig.json --noEmit
cd .. && pytest tests/test_viz_export.py
```

Что проверяет vitest:

- 20 шагов с кадрами и регионами;
- пометки чисел из чекпойнта;
- соответствие экспорта: словарь, параметры, лента клиента, веса внимания и
  предсказание;
- все символы сцены есть в обоих шрифтах — иначе troika ушла бы за шрифтом в сеть;
- причины: бит на причину, эксперименты проверок из README аудита;
- клик по 2D-экрану: элементы управления и выделение текста не листают;
- порт телеметрии и чтение файла по частям.

Тест `tests/test_viz_export.py` гоняет экспортер на синтетическом мире, а не на `data/`.
